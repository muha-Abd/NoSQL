# ADR-001 — выбор MongoDB

**Статус:** принято.

**Контекст:** библиотеке необходимо хранить карточки книг и читателей, историю выдач, даты возврата и формировать отчёты.

**Рассмотренные альтернативы:** Redis хорошо подходит для кэша, Cassandra — для больших потоков с заранее известными запросами, Neo4j — для графовых связей. Основные сценарии проекта связаны с документами и агрегациями.

**Решение:** MongoDB как основное хранилище. В документе выдачи хранятся вложенные snapshot-объекты книги и читателя. Создаются индексы по названию, жанру, читателю, статусу/сроку и ID книги.

**Последствия:** удобная документная модель и агрегации; snapshot приводит к дублированию некоторых полей, а учёт нескольких экземпляров требует дополнительной логики.
